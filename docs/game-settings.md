# 难度、自机与 Practice

[English](en/game-settings.md) · 简体中文

游戏设置由操作者在 Web 控制台选择，模型按所选场景训练，不自动决定难度或课程。选项同时用于新建训练、从检查点续训、试玩和独立评估。

## 使用方式

在训练页或模型库的“游戏设置”选择模式、难度、自机和起始关卡，再明确启动相应会话。修改选项本身不启动进程、不发送游戏按键。运行时不能修改该会话的设置。

| 设置 | 支持范围 |
| --- | --- |
| 完整流程 | Easy、Normal、Hard、Lunatic，从 Stage 1 开始 |
| Extra | 在完整流程下选择 Extra，走游戏独立入口，从 EX 开始 |
| Practice | Easy–Lunatic，可选择相应难度／自机已解锁的 Stage 1–6 |
| 自机 | 灵梦 A/B、魔理沙 A/B |

当前版本 Easy Practice 的游戏菜单最多提供 Stage 5。Extra 不通过 Practice 入口进入；Extra 及相应自机必须在游戏中已解锁。程序读取游戏的解锁记录，只通过普通按键选择，不修改存档、游戏文件或游戏内存。

若所选关卡未解锁、菜单身份未知或启动后实际难度／自机／Practice 关卡不匹配，会保留会话并等待人工处理，不悄悄换成其他难度或 Stage 1。未知值不填成 Normal／灵梦 A。

已进入关卡后立即暂停，即使原生计时只有第 0–5 帧，也可以接入。若开始时已经位于 Practice 选关页，程序会核对先前确认的设置，逐层返回修改不一致项，再进入所选关卡；它不会把选关页上的旧难度当成本次所选难度。

完整流程随游戏推进关卡；Practice 结算后重新进入所选关卡。首次校准和资源人工确认仍然需要完成，见[开发指南](development.md#首次校准与资源核对)。

## 配置与 CLI

`config.json` 可配置默认设置：

```json
{
  "game_setup": {
    "mode": "practice",
    "difficulty": "hard",
    "character": "marisa_b",
    "stage": 5
  }
}
```

这是配置片段，需要保留原有 `game_exe`、设备和保护字段。完整模板见 [config.example.json](../config.example.json)。网页选项保存在浏览器并作为启动参数提交，不覆盖本机全局配置；清除浏览器设置后回到配置中的默认值。

命令行也可指定。以下命令会真实接管游戏并训练，需在操作者准备好后执行：

```powershell
.\.venv\Scripts\python.exe -m th06ai train --minutes 5 --game-mode practice --difficulty hard --character marisa_b --stage 5
```

已有配置未包含 `game_setup`、也未传 CLI 参数时，保留原有接入能力：可以续接已开始的游戏，菜单中保留当前难度和自机选择。网页会明确提交操作者选择的完整设置。

`POST /api/sessions` 增加可选 `game_setup` 对象，字段只允许 `mode,difficulty,character,stage`，并校验组合。设置作为同一个 JSON 参数传过 CLI、独立保护进程和 worker，避免会话启动过程中再从页面读取变化中的选择。已有保护阈值、同源令牌和模型 ID 校验保持有效。

## 实际读取与菜单高亮

| 来源 | 当前固定版本的证据 |
| --- | --- |
| 难度 | RVA `0x53D410`，int32，0–4 为 Easy–Extra；菜单确认写入的指令在 `0x4CAEE` |
| 自机／机体 | `0x53CAD0/0x53CAD1` 两字节，各为 0/1；角色与机体确认分别在 `0x4CD28/0x4D32A` |
| Practice | `0x53D404`，由当前菜单的 Practice 标记复制；指令 `0x4F34F` |
| 挑战／符卡练习 | `0x53D414`／`0x53D405` 用于区分场景，不作为本轮新增可选模式 |
| 选关页面 | `NC_MENU+0x168B0 == 22`；`+0x28` 为 0 开始的高亮，不能直接当战斗关卡 |
| 可选关卡数 | `0x549D55 + (character*2+shot)*24 + difficulty`，按游戏自身规则限制；初始化逻辑 `0x57020` |
| 移速 | 玩家对象 `+0x7860/+0x7864` 及 `+0x7710/+0x7714` 的轴缩放；普通／低速读取指令 `0x6A861/0x6A854` |

这些来自当前已固定 SHA-256 的 EXE 自身，新增代码特征加入 `native.SIGNATURES`。它们不适用于未知版本，移植不能只替换哈希。

进行中的身份通过 `Frame.difficulty/character/game_mode` 和 `game_settings.source=game` 表示；轻量控制读数复用已需读取的小区块，没有增加完整弹池读取。Practice 选关页显示 `source=menu`，仅表示当前菜单选择；不会给该页面生成战斗关卡身份、速度或训练样本。

规划器在有有效原生速度时更新当前自机的快慢速，避免换自机后沿用另一自机的校准速度。速度不可读时保留未知标记，不用 0 冒充静止。

## 观测、模型和结算边界

观测 v9 在已有融合输入的末尾追加 `game_context (19,)`：难度、机体、模式各自 one-hot 与 known 位，以及快慢速和速度 known 位。网络输入使用真实读数，不把操作者请求作为观察事实。

v1–v8 模型通过兼容迁移加载。v8 已学融合列、策略、value 和 Adam 历史复制保留，19 个新输入列和新维度的 Adam 历史从零开始；迁移本身不改变旧动作概率，不重置正常的 B 分支，也不覆盖原文件。

Practice 的原生结算标记会结束该训练片段。`SamplingInterrupted.episode_end` 让采样器切断 GAE 并重置，不把结算菜单伪造成一次战斗动作或虚构通关奖励。独立评估会把这种结束记为 `practice_result`，它不表示完整游戏通关。

动作与回合日志记录实际 `game_settings`，会话另记 `requested_game_setup`，模型元数据记录所选设置及新字段顺序。难度、自机或模式发生真实变化时，时序上下文也随关卡边界隔开。
