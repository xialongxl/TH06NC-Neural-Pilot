# 易错点、隐蔽边界与排障

[English](en/gotchas.md) · 简体中文

这是接手本项目时优先阅读的文档。以下约束来自现有实现和历史故障；修改相关代码是允许的，但需要保留不变量及对应证据，不能以“清理复杂逻辑”为由删除保护和兼容性。

## 1. 游戏版本和读取

### 1.1 不能只改 SHA 让新游戏启动

涉及 `native.py/combat.py/lasers.py/stage.py/game_phase.py`。哈希、PE 布局、RVA、指令特征、池 stride、碰撞尺寸和菜单状态是一组适配证据。只改哈希或照搬旧版地址，会把其他字段误当坐标／资源，甚至产生看似合理的错误奖励。

改版本先建立新适配和只读夹具，再核对实机值；保留旧验证，不把来源不明的偏移写进 UI。验证：`test_resources.py`、`test_combat.py`、`test_enemy_contact.py`、`test_laser_geometry.py`、`test_game_phases.py`。

### 1.2 空弹幕、跨帧读取不是失败

开局几秒没有弹是正常状态。游戏与读取并行，两个批量区块的 tick 不一定相同。禁止加入“弹数为 0 就重试”“必须连续同一帧”“重试若干次直接结束训练”作为正常采样前提。

跨帧标记用于分析，真实读内存失败、结构／数值错误仍需处理。不要通过复用旧帧伪装新鲜输入。验证：`test_state_capture.py`、`test_full_bullet_observation.py`。

### 1.3 15 tick 不是采样退出时限

若两次观测间隔超过运动估计的有效范围，相关速度标为未知。它不代表整个帧、奖励或会话必须报错。资源与生存仍按实际经过的 tick 处理；不能把未知速度填写为“已知静止”。

### 1.4 `focused` 有两种不同含义

`Frame.focused` 是自机低速状态，`GameWindow.focused` 是 Windows 前台窗口。拿前者判断是否该发键会误暂停；拿后者编码低速会污染观测。

### 1.5 攻击目标不等于接触障碍

网络最多编码 32 个 Boss 优先目标，但接触判定来自原 256 槽池，且受独立接触 flags 控制。不能只避可受伤敌人、只避 Boss、只避有 HP 的已选 32 个目标。反过来，关闭接触的对象也不能被虚构成障碍。

### 1.6 激光是有方向的矩形，不是普通弹圆

读到的美术宽度不一定是碰撞宽度。本版直线激光半宽换算有实际调用证据；预告、伤害、消退也不同。转动／增长会扩大未来占据范围，只用两帧中心速度无法描述全部攻击。

不要把预告当已经伤害并触发 B 先验，也不要把另一游戏的激光池结构套来。验证：`test_laser_geometry.py`。

## 2. 场景、暂停和输入

### 2.1 冻结 tick 不足以证明暂停菜单

普通暂停、失焦冻结、脚本停帧、Boss 对话、菜单过渡都可能不推进计时。PPO 更新需要确认真实暂停条件，不允许用“差不多没动了”替代。

同时也不能因旧字段表示 ECL 停帧就否认操作者眼前的暂停菜单。核对 `phase_evidence`、新典暂停 UI、菜单选择／动画；改 `classify()` 时保留区分。验证：`test_game_phases.py`、`test_training_controls.py`。

开局第 0–5 帧也可以是已进入关卡的真实暂停。启动接入使用原生场景／活动状态，不能要求 `tick > 5` 才承认关卡；恢复与重开仍各自确认实际帧推进。否则 Practice 开局立即暂停会被错误拒绝，而只读面板却已经正确识别。

从已有的 Practice 选关页启动时，需要核对先前确认的难度、自机和机体，必要时逐层返回修改；不能直接确认当前关卡，把旧选择当成本次请求。当前菜单光标与上一层已确认值不同，不能混用。

### 2.2 对话期间不能继续随机走位

`_advance_dialogue()` 释放方向、Shift、X，只处理确认与等待。结束后强制产生新的 Z 按下边沿，避免系统已经松开、控制器却认为仍持有 Z。不要把对话耗时采成正常躲弹经验。

### 2.3 R 重开不是所有版本／画面的通用捷径

本版在正确暂停上下文使用 R，并验证计时复位与真实推进。旧计时归零或菜单动画本身不能证明进入新回合。不能为绕过重开故障改用 WASD；项目移动固定方向键。

### 2.4 发送成功与游戏生效不同

SendInput 成功只表示进入系统输入队列。主机计时、首次读到匹配方向位、位移、真实游戏帧都不同。保持相同组合时事件数为 0 是正常 held 状态，不应把它当一次零延迟新发键。

按下／松开须稳定排序，一批发送，避免重复方向或 Shift 顺序问题。游戏失焦时必须释放并进入可恢复等待。验证：`test_input_latency.py`、`test_focus_hotkeys.py`。

### 2.5 旧键在推理期间仍会生效

先读帧再花 50ms 规划，游戏不会等待。新键的最小保持应从下发后的控制样本起计，旧键作用不能抵扣。删掉规划前缀或从观测时钟开始“保持两帧”会使训练动作名与实际轨迹错位。

### 2.6 F7/F8 不需要用户按 Shift

模型可能持续持有低速 Shift，监听仍要接收到直接按 F7/F8 的事件。事件回调要轻量、按下只触发一次；F8 独立处理，不能排在繁忙的 F7 或 UI 队列后。

## 3. 规划与概率

### 3.1 风险回退不是安全证明

`all_routes_risky/fallback` 只表示当前有限搜索未找到稳健路线。可以保留有边界的脱离选择，不能把 allowed 一律写成 robust_safe，或声明“算法证明无解”。

### 3.2 典型切键安全不能覆盖其他时刻的碰撞

曾发生的关键错误是将典型时刻名义安全方向并回回退集合，而较早切键会穿弹。v8 的脱离优先规则要求完整切键区间逐 tick 检查。超宽窗口带有不完整标志，维持风险回退。

预警激光可能让所有方向在本体探测中受阻。此时优先保留通过各切键时刻普通弹和伤害几何检查的短时脱离方向，并按含预警激光的完整预测排序。启用时记录 `planner_active_threat_priority`，路线仍是回退。

不要重新引入 `allowed |= nominal_at_one_time`。真实夹具：`tests/fixtures/stage5-switch-window.npz`；验证：`test_planner_timing_recovery.py`、`test_native_search.py`。

### 3.3 全场输入和可达几何排除不同

全池可见弹进入感知，规划可在同一有限预测模型下排除不可达对象。不能按最近 64 枚裁掉风险，也不能通过减少激光／本体让 benchmark 看起来更快。密集场景可以缩减未来分支，但当前 18 个移动及返回路线的完整窗口仍保留。

### 3.4 规划、采样、执行、PPO 回算必须同分布

如果修改 planner bias、动作 mask、B 条件先验或执行逻辑，要同时检查 `policy.py/ppo_update.py/pausable_ppo.py/inference.py`。执行阶段将网络动作替换成“更安全方向”却保存原 log_prob，会破坏 PPO。

验证不仅是动作合法，还包括概率、value、日志和已执行动作一致；见 `test_planning.py`、`test_policy.py`、`test_bomb_policy.py`、`test_stage5_upgrade.py`。

### 3.5 Rust 加速不等于所有路径已原生化

`collision_backend=rust` 可能只表示 sweep。整段搜索看 `search_backend`。Python 参考路径不能删：它是可选扩展缺失时的实现，也是新原生后端的差分基准。

### 3.6 不要用硬编码回中、往上、必放 B 修补策略

墙角驻留与资源躲避需要检查观测、奖励、目标评分、历史信息和决策可行性。强制改方向破坏概率一致；靠奖励固定位置也会产生新的可利用漏洞。

## 4. 奖励与训练数据

### 4.1 擦弹不直接奖励，原始分数也不直接加分

本项目的原则是先学存活、有效位移、资源和攻击。擦弹及总分作为诊断／上下文；总分包含擦弹相关收益，直接奖励会绕过“不刻意擦弹”的设计。点道具净增仍有独立奖励，不等于完全不吃资源。

### 4.2 资源奖励有递减，Power 还有可回收的势函数

提高采 P 分数时检查 `RewardTracker`、`objectives.py`、规划目标、control 的递减历史和死亡边界。只增加拿到资源的奖励却不处理死亡重拿，会鼓励自杀循环。

库存差值是净变化：同一观测间隔中同时拾取和消耗不能总能还原全部事件。别把估计净消耗宣称成原生 B 事件计数。资源读错时也不能靠更大权重让模型“快点学会”。

### 4.3 Boss 消失不自动等于击杀

HP 重置、无敌、阶段切换、脚本扣血和传送不能无条件领伤害奖励。伤害反馈只确认同一可受伤阶段内的可信减少；最终击杀和通关奖励尚未以原生判据完整验证。

### 4.4 重复 B 请求和实际消耗不同

安全场景初始 B 先验为 0.00005；生存模式的严格危急窗口可用 0.01 条件先验，仍不是自动执行 B。NMNB 或库存为 0 会屏蔽 B。不要恢复联合熵直接鼓励 B=50% 的旧设计。

### 4.5 真实 Miss 可能只存在于轻量样本

完整帧已经是复活状态不代表刚才没死。保留 `death_probe_tick/death_evidence`，首次中弹终止本局。不能因结果帧 state 不为 2 就抹掉死亡成本。

### 4.6 跨关、时钟归零和暂停会污染时序历史

清理子弹／敌机／激光速度与驻留，隔开 GAE；保留整局资源、学习计数和真实转移。不要伪造 death、重开或通关奖励。验证：`test_stage_awareness.py`、`test_sampling_timing.py`。

### 4.7 会话预算与生存秒数不是同一时钟

单局默认不按 180 秒截断。训练会话的计划时长最多 60 分钟，扣除用户暂停和有控等待。游戏暂停中的 PPO 更新仍计入训练。到点时只允许当前已识别关卡加时，最多 10 分钟。剧情进入下一关、结算或本次尝试结束即收尾，避免到点后自动重开。生存／关卡时间按原生战斗 tick，未采样间隔单独记账，不凭空补奖励。

### 4.8 训练日志不能替代独立评估

比较不同奖励版本总 reward 没有直接意义。评估固定权重，检查完成局数、目标、B 使用、Miss、关卡及资源。存活到截断或部分十局报告不是通关，更不是完整 NMNB。

## 5. 保存、兼容与并发

### 5.1 不覆盖唯一模型，不反复修复 v2 的炸弹头

修改 `learning.py/model_store.py` 必须保留原文件、兼容参数和 Adam 状态。追加融合列从零影响开始，原优化器不应整套重置。只有明确新建模型才使用随机权重。

`latest.zip` 与 JSON 哈希不一致时拒绝加载／覆盖。不要为了“恢复方便”关闭校验。真实尚未更新的新模型不能保存成已训练模型。

### 5.2 暂停恢复不是磁盘续训

F7 保留同一进程、缓冲和回合；新 worker 从检查点开始新会话和回合。磁盘模型没有游戏 RAM 或完整中途 rollout。按钮和提示不能混用“继续”。

### 5.3 不能在 Windows 用普通长持有读取阻挡原子替换

`files.read_json()` 使用共享删除权限，避免 UI 读者阻挡 `os.replace()`。改回常规持有文件句柄、扫描锁定状态文件，可能再次导致 `current.json.*.tmp -> current.json` PermissionError。

真实授权走共享内存，不应重新依赖 JSON 文件的新旧时间。原子 JSON 重试有边界，不能无限等文件。

### 5.4 授权忙与授权新鲜不同

`LeaseBusy` 只允许复用最后一次完整有效记录，保持原 GPU 采样时刻。用当前重读时间刷新年龄，会把坏显卡／失联监控“永远续期”。反之，一次并发写就直接报授权失效会导致误停。

### 5.5 Rust 中不能跨 detach 借用可变 NumPy

先形成拥有型快照，再释放 GIL。输入控制器的 held 和事务串行。不要仅因“Rust 内存安全”就删 Python 锁或把无生命周期保证的指针传过去。

### 5.6 CUDA Graph 可能读到旧参数或绕过错误

保持图执行和训练的参数存储一致；观测、value 和 log_prob 必须对应同一次动作。只将图捕获限制作为 auto fallback，OOM、非法访问、设备丢失不能吞掉转 CPU。

## 6. 保护、性能与发布

### 6.1 GPU 保护不能挪进 worker

worker 卡在驱动／模型时仍要停机。保留独立采样、F8、Job、共享授权与锁存故障。正常保存不是硬件故障时的前置条件；不能等 CUDA save 结束才停止计算。

### 6.2 15% Torch 限额不是整张显卡只占 15%

上下文、驱动和其他程序也占显存；独立保护看全卡总量。因总显存超过 90% 停机时，不应只检查本项目 allocator。空闲低温风扇 0 也可以正常，不能一概认作物理损坏。

### 6.3 缺失传感器不能冒充零值

显存温度／ECC 等首次不支持时标为不可用；已支持的读数中途丢失要区别处理。软件无法保证检测所有硬件故障，README 不应写“任何异常都绝对立即检测”。

### 6.4 `.cache` 大不代表每步训练在读它

它包含下载分片、解包、测试和编译缓存。运行依赖在 `.venv`，模型在 models；uv 还可能使用硬链接，逻辑大小不能直接等同可释放空间。Git 忽略即可，不必为 push 删除本机缓存。

### 6.5 各阶段独立 P95 不能相加

先按同一动作时间戳拆分，再统计。设备流跨度包含传输／内核／调度，与主机推理时间有包含关系；只读复测没有 SendInput 或完整训练回调。不能用不同场景两批 P95 相减宣称严格成对提速。

### 6.6 不靠默认硬编码 CPU 核号修延迟

性能核／能效核和调度会影响结果，但单次亲和性或 QoS 对照不能证明历史唯一原因。不要固定作者电脑的逻辑 CPU 编号或悄悄改系统电源计划。

### 6.7 Web 不是公网服务，刷新不是会话控制

不删 token、Origin、项目身份与模型 ID 校验。端口被占用时核对归属，不按名字／端口杀其他项目。页面断线、关闭或 StrictMode 订阅重建不能重复开训或重复切换 F7。

### 6.8 gitignore 不会清理已提交历史

先检查 `git ls-files`／暂存区。公开前排除个人 config、校准、日志、模型、缓存及二进制。不要把“从 Git 撤出索引”误写成删除本地目录；已经公开过的敏感信息需另行处理历史及凭据。

### 6.9 MIT 与非商用倡议不同

标准 MIT 允许商业使用；项目采用标准 MIT，非商业研究是用途倡议，不加禁商用限制。原作及第三方权利另行适用，详见[免责声明](../DISCLAIMER.zh-CN.md)。不要擅自把它改成“MIT 禁止商用”。

## 快速排障顺序

先看当前 `status/result` 的 reason、worker 异常栈和实际场景，再按问题分到：版本／采集、焦点／菜单、授权／硬件、动作时序、策略／奖励、UI 历史显示。保留原始证据，区分直接测量与推断；不要用一连串不相关新限制掩盖根因。
