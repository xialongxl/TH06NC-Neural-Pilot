# 给未来 AI 的交接信

[English](en/ai-handoff.md) · 简体中文

你接手的是 **TH06NC-Neural-Pilot**，作者署名为 **xialongxl**，代码采用标准 MIT。它是个人与 AI 协作构建的实验性实时系统。不要因为代码主要由 AI 辅助产生，就把现有边界当作可以随意清理的历史包袱；其中不少是通过真实失败才发现的契约。

## 设计哲学

我们希望学到的行为可以解释、记录和验证。神经网络负责可学习策略，滚动规划把当前可观测几何变成可检查的路线评价，两者共同形成一个 PPO 可以正确回算的分布。外围状态机负责接入与菜单，独立保护负责在模型或驱动失灵时仍能停机。没有“用脚本伪装 AI”，也不相信把一句原则放进说明书就能让神经网络理解。行为目标必须落实到观测、奖励、概率、边界和评估。

另一个同样重要的原则是：不要为了让系统看起来更安全而制造一连串正常场景下的误停。空弹幕、并行跨帧、未匹配输入位、普通失焦和未知运动各有语义；真实硬件异常和失去授权才走对应紧急路径。

## 第一个工作时段应该做什么

1. 读根目录 [AGENTS.md](../AGENTS.md)、[架构](architecture.md)和[易错点](gotchas.md)。
2. 用 [ai-context.json](ai-context.json) 找变更领域与相关测试，再用 [code-index.json](code-index.json) 找真实符号。
3. 检查当前源码、版本常量、实际 config 和会话是否运行。不要把历史报告、UI 上次采样、README 的本机基线当成现状。
4. 说明哪些操作只读、哪些会发键／使用 GPU／更新模型。没有明确授权时不自动启动真实训练或接管。
5. 针对问题收集最小证据，先作相关离线复现，再修改；不要一开始就要求用户重训几个小时。

## 当前架构事实，别靠猜

```text
React + TypeScript
  → loopback REST + versioned SSE JSON
  → ConsoleService（会话意图／文件状态）
  → supervisor（独立NVML/F8/Job/lease）
  → worker（GameReader/Planner/Policy/PPO）
```

- 当前没有数据库、远程调度器、WebSocket、MsgPack 或浏览器端模型。
- 配置是 config.json，没有自动 dotenv；示例环境变量不能当作已实现设置。
- 低频 UI 推送与高频动作、250ms GPU 采样分离。CPU 诊断子进程经有界私有管道接收 owned 数据，压缩与动作行编码不在控制线程。
- CPython 包名和 CLI 仍是 th06ai；不要因项目展示名重命名序列化类路径。
- 个人游戏路径只在 Git 忽略的本机 config，根目录由代码位置推导。
- 默认原生构建安装 native_runtime（ABI v3，含 Q 与只读批量采集）；旧 native_planner 作为独立搜索兼容路径。扩展缺失有参考路径。
- 难度、自机与 Practice 由操作者选择；请求与原生读数分开。观测 v9 追加 19 维上下文，v8 迁移保留原列和 Adam；Practice 结算切断 GAE，不伪造战斗动作。参见[游戏设置](game-settings.md)。

## 历史上反复发生过的错误

- 用更多存活奖励和简单贴边扣分，模型找到待墙角的局部收益。
- 只奖励拿 P，不处理死亡与重拿，或丢掉资源递减历史，制造错误目标。
- 用普通联合熵鼓励炸弹，导致空场不断放 B。
- 只避子弹、不避敌机本体，或从攻击目标列表裁掉接触威胁。
- 把图像宽度当激光碰撞尺寸，漏掉激光阶段与朝向。
- 只检查典型延迟，随后把已在其他切键时刻判碰撞的方向重新放行。
- 认为最终完整帧复活了就没发生 Miss，抹掉真实死亡。
- 要求读取严格同帧／开局必须有弹，正常运行几分钟后误退出。
- 把旧 ECL 停帧当普通暂停，把游戏已暂停误报为没暂停。
- UI 刷新、关闭或“继续训练”语义混乱，造成重开／重复会话。
- 只测内核最快耗时，却宣传整条实机链已经低于 2ms。

这些不是要求永远不改原实现，而是要求任何新方案显式覆盖对应反例。

## 改动时必须一起核对的文件

| 你要改 | 不要漏掉 | 否则可能出现 |
| --- | --- | --- |
| 观测 shape／列序 | observations、policy融合层、learning迁移、inference缓冲、轨迹记录 | 老模型错位、CUDA图输入错误、Adam丢失 |
| 规划 mask／偏置 | Python/Rust、ResourcePolicy、PPO回算、死亡夹具 | 执行与概率不一致，早切键穿弹 |
| 奖励／目标 | objectives、历史control、死亡／阶段边界、独立评估 | 自杀刷资源、墙角驻留、分数不可比较 |
| B 行为 | policy_spec、policy、ppo_update、目标可用性、迁移 | 再次狂B或重复重置已学分支 |
| 暂停／重开／跨关 | environment、TrainingControl、PausablePPO、相位解码 | 游戏运行中更新、GAE污染、假转移 |
| 快捷键／输入 | GlobalHotkeys、Win32/Rust held、focus、独立Job | 持Shift不响应、卡键、误杀其他进程 |
| 状态传输 | display DTO、SSE base/revision、前端引用协调、tests | 多标签页放大采样、断层状态、重绘过量 |
| 保存／模型库 | ZIP及JSON、哈希、immutable历史、迁移状态 | 唯一模型被覆盖或无法续训 |
| 保护 | SafetyPolicy、AsyncTelemetry、SharedLease、supervisor、Heartbeat | 驱动卡死时无法停止、授权永远续期 |

## 风格与范围

沿用现有小模块、dataclass、明确输入输出和领域版本。新增注释解释单位、边界和理由，少写“函数做了什么”的逐行复述。为真实反例和数学／并发契约写测试，不为改文案镜像实现。

保持 React 前后端分离；旧 Tk 仅是兼容工具。不要把修复 bug 的技术说明塞到用户按钮，不为一个性能问题新增与其无关的操作确认或停训条件。

私人的缓存、模型、日志与校准都留在本机。开源通过当前 Git 根目录和忽略规则，不需要删掉用户环境。标准 MIT 的用途倡议不是禁商用附加条款；原作和第三方权利说明单独保留。

## 验证与交付

按 [测试矩阵](testing-and-performance.md) 跑相关回归。改原生搜索时必须保留 Python 差分、完整弹池、本体／激光、时序窗口、fallback 和并发。改策略时比较 action/value/log_prob，不只看能否跑完一次 forward。

文档或源码定位变化后更新 code-index，再运行 check_docs。若涉及实际接管，清楚记录操作者授权、场景、目标、是否更新模型和保护设置。只读测试结束就结束诊断进程，不偷偷留下训练。

交付时说明已完成内容与实际验证，指出缺失证据；不要因为用户着急而声称“已经学会”“模型没问题”“绝对安全”。本机基线已经证明性能有收益，尚未证明稳定完整 NMNB、通用游戏版本或整链 2ms。

## 仍可改进的方向

- 新机器资源确认自助界面与可审查校准流程。
- 多版本适配、更多激光／特殊攻击和真实通关判据。
- 更完整的 Python 依赖锁、跨机器验收和自动 CI。
- 在真实会话中继续分析读取、PPO回调与发键确认的慢尾，保留同动作时间线。
- 公开脱敏的评估协议与必要夹具，让报告可由其他开发者复核。

优先从用户的实际问题和现有证据出发，不把这份愿望清单当作自动授权的新任务。
