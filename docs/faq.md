# 常见问题

[English](en/faq.md) · 简体中文

这份文档面向第一次安装、日常训练和准备参与开发的使用者。完整操作见[开发者指南](development.md)，实现边界见[易错点与排障](gotchas.md)，项目入口见 [README](../README.zh-CN.md)。

## 它是神经网络 AI，还是固定按键脚本

移动决策包含可训练的 PPO 策略网络，并结合当前弹幕、敌机本体、激光及控制时序进行滚动路径搜索。训练会根据实际转移和奖励更新网络权重；试玩和评估只使用固定权重。

菜单确认、对话、暂停和重开由外围状态机处理。这些操作不作为躲弹学习样本。规划器只能根据已经观测到的状态做有限窗口预测，不读取未来出弹计划。具体协作方式见[核心逻辑](core-logic.md)。

## 有现成模型吗，多久能学会

仓库不包含作者的模型 ZIP，也不承诺某个训练时长就能稳定通关。没有兼容检查点时，从“新建模型”开始；已有自己训练的兼容模型时，在模型库选择后续训或试玩。

首次建议短会话核对输入、资源、射击、暂停和日志，再安排更长训练。不同场景、目标、奖励版本与设备会影响结果。奖励上升或某次存活很久不能替代固定权重评估，更不能直接证明完整 NMNB；评估范围见[测试与性能](testing-and-performance.md)。

## 首次运行为什么还不能开始训练

安装依赖、打开网页和完成移动校准是不同步骤。当前首次接入有三项检查：

| 检查 | 用途 | 本机记录 |
| --- | --- | --- |
| GPU 自检 | 确认所选设备及训练后端能工作 | `training_backend.json` |
| 实机校准 | 验证移动、低速、弹幕读取和重开 | `native_calibration.json` |
| 资源人工核对 | 确认读取的 Power、B、残机与游戏画面一致 | `native_resources_calibration.json` |

**资源确认还没有完整的 UI 自助流程。** 自动移动校准不会创建资源确认记录；具体的只读核对命令、文件位置和模板见[首次校准与资源核对](development.md#首次校准与资源核对)。文件属于本机，不随源码分发，也不能从其他人的机器复制后直接视为验证通过。

在只想查看界面时，可以使用 `open --preview`。预览禁止启动训练或发送游戏按键，不会把未知数据填成示例成绩。

## 为什么用了 GPU 仍有 CPU 占用，Rust 必须安装吗

CUDA 主要承担策略网络训练和推理；游戏读取、场景处理、规划、输入、日志和操作系统调度仍会使用 CPU。观察到 CPU 占用不等于网络没有使用 GPU。

Rust/PyO3 是可选加速路径，用于碰撞、搜索与输入的相应实现。未安装时有 Python 参考实现可用；手动指定 `rust` 与选择 `auto` 的行为需要区别。构建方式见 [native README](../native/README.zh-CN.md)，实际后端以诊断记录为准。

当前真实游戏会话仍依赖 NVIDIA NVML 独立保护。将配置改成 `device=cpu` 只改变网络设备，不代表已经支持无 NVIDIA 的完整实机运行模式。Rust 也不等于整条控制链保证低于 2ms，测量口径见[性能说明](testing-and-performance.md)。

## 暂停恢复和续训有什么区别

| 操作 | 会话、游戏与学习状态 |
| --- | --- |
| F7 暂停后恢复 | 继续同一进程、当前回合和尚在内存中的采样缓冲 |
| 保存结束后从检查点续训 | 新建会话与回合，恢复已保存权重、兼容优化器及累计学习进度 |
| F8 紧急停止后再续训 | 从最近一次成功保存的检查点恢复，未保存工作可能丢失 |

模型检查点不包含完整游戏内存，也不包含中断时全部未完成采样。暂停使用直接按 F7，紧急停止直接按 F8，无需组合 Shift；模型按住 Shift 时也应能响应。

## 关闭网页后训练会结束吗

刷新或关闭网页不会结束后台会话。重新打开控制台可以查看现有会话，不需要再次点击新建训练。

正常结束使用“保存并结束”；关闭整个后端使用“关闭服务”或根目录的 `关闭AI.cmd`，它会请求保存并等待会话退出。硬件异常或需要立刻停止时使用 F8；紧急停止不等待模型保存。不要把关闭网页当作停止操作。

## 生存练习和 NMNB 为什么要分开

`survival` 允许学习在危急情况下使用 B，`nmnb` 屏蔽炸弹动作。允许使用 B 不代表系统保证每次必死时都会放 B；有限预测和可训练策略仍可能判断失败。

比较结果时要同时看目标、Miss、实际 B 消耗、关卡与完成局数。使用 B 后的存活应与 NMNB 分开报告。资源、奖励和动作条件见[数据契约](data-contracts.md)与[核心逻辑](core-logic.md)。

## 会奖励 P 点、攻击和擦弹吗

资源拾取、Power 与攻击反馈参与训练和规划目标；资源收益会考虑递减及死亡后重复拾取，避免通过自杀重拿获得虚假进步。奖励存在不意味着策略已经可靠学会相应行为，需要检查实际拾取、Power 和有效伤害。

擦弹不直接给予训练奖励，总分也不直接整笔加到奖励上。设计目标是先学会存活、资源和攻击，顺路擦弹作为结果观察。若出现长期死磕角落、避开资源或撞敌机，应按实际快照排查观测、奖励和规划，不能仅用“还没学会”解释。相关边界见[奖励与训练数据](gotchas.md#4-奖励与训练数据)。

## 为什么有 60 分钟预算，还会出现 180 秒设置

会话预算与单局战斗时间是两套时钟。当前会话最长 60 分钟；用户暂停和受控等待会单独处理，游戏暂停中的 PPO 参数更新仍是训练工作。

公开示例的 `episode_seconds=0`，表示不按单局时长截断。已经存在的 `config.json` 不会被安装脚本覆盖，因此旧配置可能仍保留 `180`。需要改变时先核对自己的配置，不要把旧值误认为当前源码默认。具体计时语义见[易错点](gotchas.md#47-会话预算与生存秒数不是同一时钟)。

## 前端会拖慢训练吗，使用的是 WebSocket 吗

当前前端通过 REST 发出明确操作，通过增量 SSE 接收状态，传输格式为 JSON。可见页面最多 2Hz 推送，无变化只发小心跳；所有订阅页面隐藏时降为 0.2Hz，没有订阅时停止界面采样。

实时读状态、规划、网络推理和按键不经过浏览器；多个页面共享后端界面采样，慢客户端合并到最新状态。日志和显示仍有一定系统开销，不能声称完全零影响。GPU 保护独立以 250ms 采样，不随 UI 降频而减慢。协议细节见[前端说明](../frontend/README.zh-CN.md)。

## 更新游戏或项目后需要注意什么

游戏版本适配绑定 EXE 哈希、代码特征与结构，当前已验证版本见 [README](../README.zh-CN.md#使用前需要知道)。游戏更新后不能只改哈希绕过检查，也不能复制旧版内存偏移继续训练。

更新项目代码前，先保存并结束会话，让新会话重新加载代码。观测、奖励、策略、规划、输入计时及原生 ABI 有独立版本；历史模型应保留原文件，兼容迁移不能随意重置已学参数和优化器。失败时先记录兼容性原因，不删除唯一检查点。开发者修改前读[数据契约](data-contracts.md)和[AI 交接信](ai-handoff.md)。

## 报错时应该提供什么

先记录当前操作、游戏场景、项目提交和状态条中的完整原因。涉及进程退出时，提供对应会话 `worker.log` 的异常栈，以及必要的 `status.json`、`result.json` 字段；涉及行为时补充关卡、模式、目标、动作或死亡编号。

性能问题需要说明计时范围、样本数和分位数，不把模型推理耗时当作完整发键延迟。不要直接上传整个 `runs`、模型、游戏文件或本机校准；先移除个人路径、GPU UUID、令牌和不相关信息。具体格式见[贡献指南](../CONTRIBUTING.zh-CN.md)。

## 能直接打包成 EXE 或部署到服务器吗

当前已说明并验证的分发方式是源码检出、本机安装、构建前端，然后在 Windows 回环地址使用控制台。构建后的界面由 Python 服务提供，运行时不需要常驻 Vite，也没有数据库服务。

单文件 EXE、包含静态资源的完整 wheel、Docker、Linux 实机和公网多用户部署尚未验证。不要将 `pip wheel` 成功等同于完整桌面打包，也不要直接把本机服务改为公网绑定。构建范围见[开发者指南](development.md#7-构建git-发布与部署)。
